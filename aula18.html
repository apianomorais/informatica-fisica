Aula 18 · Programação em Python

Entrada e saída: teclado, arquivos e CSV

Programas úteis conversam com o mundo: leem do teclado, leem e escrevem arquivos, e não quebram quando o dado vem errado.

1. O programa que pergunta: input()

Todos os programas que escrevemos até aqui tinham os dados escritos no meio do código. Para mudar o comprimento do pêndulo era preciso abrir o arquivo, achar a linha L = 0.5 e editá-la. Isso funciona enquanto o programa é seu e roda uma vez. No momento em que outra pessoa precisa usá-lo, ou em que você mesmo precisa repeti-lo com vinte conjuntos de dados, o dado tem que vir de fora.

A porta mais simples é o teclado. A função input() para o programa, espera que alguém escreva algo e aperte Enter, e devolve o que foi escrito.

Conceito chave input() sempre devolve texto. Mesmo que a pessoa escreva 42, o que chega ao programa é a cadeia de caracteres "42", e não o número 42. Somar dois desses resultados concatena ("42" + "7" é "427"). A conversão para número é sempre sua responsabilidade: float() ou int().
Exemplo 18.1: período de um pêndulo pedido ao usuário 
import math

L = float(input("Comprimento do pendulo (m): "))
g = 9.81

T = 2 * math.pi * math.sqrt(L / g)
print(f"Periodo = {T:.4f} s")

Repare em duas coisas. A mensagem dentro de input() diz a unidade, porque quem digita precisa saber se o número vai em metros ou em centímetros. E o float() envolve o input() na mesma linha, o que é o jeito compacto de escrever, mas esconde um problema: se a pessoa escrever cinquenta, o programa quebra com ValueError e tudo o que já tinha sido calculado se perde. A seção 2 resolve isso.

Exemplo 18.2: várias entradas e uma saída formatada 
nome = input("Nome da substancia: ")
m = float(input("Massa (kg): "))
c = float(input("Calor especifico (J/kg.K): "))
dT = float(input("Variacao de temperatura (K): "))

Q = m * c * dT

print()
print(f"Substancia: {nome}")
print(f"Calor trocado: {Q:.1f} J  ({Q/4186:.3f} kcal)")
Cuidado Em português escrevemos 1,5 e o Python espera 1.5. A vírgula faz float("1,5") levantar ValueError. Como o aluno vai digitar vírgula (é o que o teclado e o hábito pedem), vale trocar antes de converter: bruto.replace(",", "."). Esse detalhe de uma linha é o mesmo problema que apareceu na unidade de planilhas, onde o ponto decimal era lido como separador de milhar.

2. Validar a entrada: try, except e o laço que insiste

Um erro de digitação é a coisa mais previsível do mundo, e ainda assim a reação padrão do Python é interromper o programa inteiro. A estrutura try/except permite tentar uma operação que pode falhar e decidir o que fazer quando ela falha, em vez de deixar o interpretador decidir por nós.

Conceito chave O bloco try contém o código que pode dar errado. Se uma exceção acontece dentro dele, a execução pula imediatamente para o except correspondente ao tipo daquela exceção. Se nada dá errado, o except é ignorado. Os tipos que mais aparecem aqui são ValueError (o texto não é um número), ZeroDivisionError e FileNotFoundError (o arquivo não existe).
Exemplo 18.3: a conversão protegida 
bruto = input("Massa (kg): ")

try:
    m = float(bruto.replace(",", "."))
except ValueError:
    print(f"Nao entendi '{bruto}'. Vou usar 1 kg.")
    m = 1.0

print(f"Massa usada: {m} kg")

O programa acima não quebra, mas também não é satisfatório: chutar 1 kg quando o usuário erra é inventar um dado. O que se quer de verdade é pedir de novo, quantas vezes forem necessárias, e só seguir adiante quando a entrada for válida. Esse é um laço while True com return na saída bem-sucedida.

Exemplo 18.4: uma função de leitura que não aceita lixo 
def pede_numero(mensagem, minimo=None, maximo=None):
    """Le um numero do teclado e insiste ate que ele seja valido."""
    while True:
        bruto = input(mensagem).replace(",", ".")
        try:
            valor = float(bruto)
        except ValueError:
            print(f"  '{bruto}' nao e um numero. Exemplo valido: 1.5")
            continue
        if minimo is not None and valor < minimo:
            print(f"  O valor deve ser pelo menos {minimo}.")
            continue
        if maximo is not None and valor > maximo:
            print(f"  O valor deve ser no maximo {maximo}.")
            continue
        return valor


L = pede_numero("Comprimento do pendulo (m): ", minimo=0.01, maximo=10)
n = pede_numero("Numero de oscilacoes cronometradas: ", minimo=1)
print(f"L = {L} m, n = {n:.0f} oscilacoes")

Vale olhar o que essa função faz de verdade, porque ela é o padrão que você vai copiar para o resto do curso. Ela trata dois tipos de erro diferentes com a mesma resposta: o erro de forma (não é número) e o erro de faixa (é número, mas impossível). Um comprimento de pêndulo negativo passa pelo float() sem reclamação alguma, e é justamente o tipo de dado que produz uma raiz de número negativo três linhas depois. O continue manda o laço começar outra vez, e o return é a única saída.

Na bancada Validar faixa não é preciosismo de programador. Num experimento de calorimetria, uma temperatura final fora do intervalo entre as duas temperaturas iniciais é fisicamente impossível, e detectar isso na hora da digitação custa uma linha de código. Descobrir depois, quando o calor específico sai negativo, custa a repetição do experimento.

3. Arquivos de texto: abrir, escrever, ler

O teclado resolve três ou quatro dados. Uma tabela de cinquenta medidas pelo teclado é tortura, e pior, é volátil: ao fechar o programa, tudo o que foi digitado desaparece. Os dados de um experimento precisam viver num arquivo.

A função open() abre um arquivo e devolve um objeto por onde se escreve ou se lê. Os modos que importam são "r" para ler (o padrão), "w" para escrever do zero, apagando o que havia, e "a" para acrescentar ao fim.

Cuidado O modo "w" apaga o conteúdo anterior no instante em que o arquivo é aberto, antes mesmo de qualquer escrita. Abrir por engano o arquivo das suas medidas em modo "w" destrói o experimento. Quando houver dúvida, escreva num arquivo de nome diferente e compare depois.
Conceito chave Use sempre with open(...) as f:. O with fecha o arquivo automaticamente ao sair do bloco, inclusive quando acontece um erro no meio. Sem isso, um programa que quebra no meio da escrita pode deixar o arquivo incompleto no disco, porque o que foi escrito ainda estava na memória esperando para ser gravado.
Exemplo 18.5: gravar uma tabela calculada 
g = 9.81

with open("queda.txt", "w", encoding="utf-8") as f:
    f.write("# tempo(s)  posicao(m)  velocidade(m/s)\n")
    for i in range(11):
        t = 0.1 * i
        x = 0.5 * g * t**2
        v = g * t
        f.write(f"{t:.1f}  {x:.4f}  {v:.3f}\n")

print("Arquivo queda.txt escrito.")

Duas escolhas aí dentro não são decorativas. O \n no fim de cada write é obrigatório, porque write não pula linha sozinho (diferente de print), e sem ele a tabela inteira sai numa linha só. E encoding="utf-8" deveria estar em todo open que você escrever: sem ele o Python usa a codificação padrão do sistema, que varia entre o Windows e o Linux, e o arquivo com acentos que abre bem no seu computador aparece corrompido no do colega.

Exemplo 18.6: ler de volta, pulando o cabeçalho 
tempos = []
posicoes = []

with open("queda.txt", encoding="utf-8") as f:
    for linha in f:
        if linha.startswith("#") or not linha.strip():
            continue              # comentario ou linha vazia
        campos = linha.split()
        tempos.append(float(campos[0]))
        posicoes.append(float(campos[1]))

print(f"{len(tempos)} pontos lidos")
print(f"ultimo instante: {tempos[-1]} s, posicao {posicoes[-1]:.4f} m")

Percorrer o arquivo com for linha in f lê uma linha por vez, o que significa que o programa funciona igual com dez linhas ou com dez milhões: só uma está na memória em cada instante. A alternativa f.read() traz tudo de uma vez e é cômoda para arquivos pequenos. O teste com startswith("#") é o que faz o cabeçalho ser ignorado sem precisar contar linhas, e ele continua funcionando quando você acrescentar mais comentários no arquivo depois.

Exemplo 18.7: o arquivo que pode não estar lá 
nome = input("Nome do arquivo de dados: ")

try:
    with open(nome, encoding="utf-8") as f:
        linhas = f.readlines()
except FileNotFoundError:
    print(f"Nao achei '{nome}'. Confira se ele esta na mesma pasta do programa.")
    linhas = []

print(f"{len(linhas)} linhas")

Esse except FileNotFoundError cobre o erro mais comum de todos no Spyder: o arquivo existe, mas numa pasta diferente da pasta de trabalho do console. A mensagem que dissemos ao usuário aponta exatamente para essa causa, e é por isso que uma mensagem de erro escrita por você vale mais que a mensagem genérica do Python.

4. CSV: o formato que a planilha e o Python compartilham

Separar os campos por espaços dá conta de uma tabela de números, e falha no primeiro campo de texto que contenha um espaço. O formato CSV (comma-separated values) resolve isso com uma regra simples: um registro por linha, campos separados por um delimitador, e campos que contenham o delimitador vêm entre aspas. É o formato que o Google Planilhas e o Excel exportam e importam, o que faz dele a ponte natural entre a unidade I e esta unidade.

Conceito chave O módulo csv da biblioteca padrão cuida das aspas, dos delimitadores e das quebras de linha dentro de um campo. csv.reader devolve cada linha como lista de textos, csv.DictReader devolve um dicionário usando a primeira linha como nomes das colunas, e csv.writer escreve. Em todos os casos os valores continuam sendo texto: a conversão com float() é sua.
Cuidado Abra o arquivo com newline="" ao usar o módulo csv. Sem isso, no Windows o arquivo escrito sai com uma linha em branco entre os registros. E note o delimitador: uma planilha configurada em português costuma exportar com ponto e vírgula, porque a vírgula já é o separador decimal. Nesse caso use csv.reader(f, delimiter=";").
Exemplo 18.8: escrever um CSV de medidas 
import csv

medidas = [
    (1, 0.200, 0.8980),
    (2, 0.200, 0.8975),
    (3, 0.400, 1.2701),
    (4, 0.400, 1.2698),
    (5, 0.600, 1.5551),
    (6, 0.600, 1.5559),
]

with open("pendulo.csv", "w", newline="", encoding="utf-8") as f:
    escritor = csv.writer(f)
    escritor.writerow(["n", "L_m", "T_s"])     # cabecalho
    escritor.writerows(medidas)                # todas as linhas de uma vez

print("pendulo.csv escrito com", len(medidas), "medidas.")
Exemplo 18.9: ler com DictReader 
import csv

with open("pendulo.csv", newline="", encoding="utf-8") as f:
    leitor = csv.DictReader(f)
    for registro in leitor:
        L = float(registro["L_m"])
        T = float(registro["T_s"])
        print(f"L = {L:.3f} m  ->  T = {T:.4f} s")

A vantagem do DictReader aparece quando alguém acrescenta uma coluna no meio da planilha. Com csv.reader e índices, campos[2] passa a apontar para outra grandeza e o programa calcula silenciosamente a coisa errada. Com os nomes das colunas, registro["T_s"] continua sendo o período, e o programa quebra de forma visível se a coluna mudar de nome.

5. Um programa completo: do arquivo bruto ao resultado

Vamos juntar as quatro peças num programa de verdade, do tipo que você vai escrever para um relatório de laboratório. Ele lê um CSV com medidas repetidas do período de um pêndulo para vários comprimentos, agrupa as repetições, calcula média e desvio padrão de cada grupo, extrai \(g\) de cada comprimento e escreve um segundo CSV com o resultado, pronto para voltar à planilha ou virar gráfico na aula anterior.

Exemplo 18.10: o pipeline completo 
import csv
import math
import statistics

ENTRADA = "pendulo.csv"
SAIDA = "resultado.csv"

# ---- 1. leitura, agrupando os periodos por comprimento
dados = {}
try:
    with open(ENTRADA, newline="", encoding="utf-8") as f:
        for registro in csv.DictReader(f):
            L = float(registro["L_m"])
            T = float(registro["T_s"])
            dados.setdefault(L, []).append(T)
except FileNotFoundError:
    print(f"Arquivo '{ENTRADA}' nao encontrado.")
    raise SystemExit

# ---- 2. estatistica e g para cada comprimento
linhas = []
valores_g = []
for L in sorted(dados):
    periodos = dados[L]
    T_medio = statistics.fmean(periodos)
    desvio = statistics.stdev(periodos) if len(periodos) > 1 else 0.0
    g = 4 * math.pi**2 * L / T_medio**2
    valores_g.append(g)
    linhas.append([L, round(T_medio, 4), round(desvio, 4),
                   len(periodos), round(g, 3)])

# ---- 3. escrita do resultado
with open(SAIDA, "w", newline="", encoding="utf-8") as f:
    escritor = csv.writer(f)
    escritor.writerow(["L_m", "T_medio_s", "desvio_s", "n", "g_m_s2"])
    escritor.writerows(linhas)

# ---- 4. resumo na tela
g_medio = statistics.fmean(valores_g)
erro = statistics.stdev(valores_g) / math.sqrt(len(valores_g))
print(f"{len(linhas)} comprimentos processados -> {SAIDA}")
print(f"g = {g_medio:.3f} +- {erro:.3f} m/s2")

Com as dez medidas do exemplo 18.8 estendidas até \(L = 1{,}000\) m, duas repetições por comprimento, a saída é g = 9,797 ± 0,003 m/s², com os cinco valores individuais entre 9,790 e 9,803 m/s². O erro de 0,003 m/s² é o erro padrão da média dos cinco valores de \(g\), e não a incerteza do experimento: ele mede só a dispersão entre comprimentos, e ignora o erro sistemático da régua e do disparo do cronômetro, que é justamente o que a aula 4 da unidade de planilhas discute.

A divisão do programa em quatro trechos comentados não é enfeite. Cada um deles pode ser trocado sem tocar nos outros: a leitura passa a vir de um arquivo com ponto e vírgula, a estatística passa a usar NumPy, a escrita passa a gerar um gráfico com Matplotlib. Essa é a forma de todo programa de análise de dados que você vai escrever, e é também a estrutura que o Pandas automatiza na próxima aula.

Na bancada Guarde sempre o arquivo de dados brutos e nunca o sobrescreva. O programa lê pendulo.csv e escreve resultado.csv, dois nomes diferentes de propósito. Quando um resultado estranho aparecer três semanas depois, o dado bruto é a única coisa que permite descobrir se o erro estava na medida ou no processamento.
